# First-release requirement audit

Audited against [the accepted implementation plan](../IMPLEMENTATION_PLAN.md), November 16, 2026. All seven implementation phases meet their local exit criteria. The final build, compatibility matrix, independent publication consumers, streaming smoke suites, and claimed native-image checks pass; benchmarks and compatibility documentation accompany the candidate. The historical WebFlux drain timeout is preserved below with an unknown cause. Verification applies to the stated framework/runtime/operating-system combinations.

## Historical timeout and verification limits

A subsequent [Java 17 launcher regression check](verification/2026-11-16/java17-launch/README.md) passes the full build, compatibility matrix, and independent consumers after adding Java 25 daemon criteria. It also verifies provisioning from a Java 17 shell. This corrects build startup; library production sources and bytecode targets are unchanged.

The [WebFlux drain investigation](benchmarks/2026-11-16/http/webflux-drain-audit/README.md) began with a timeout while draining a sparse NDJSON warmup window. The original failure recorded 356,373 expected records but no delivered count. Earlier status wording described a count mismatch; the available evidence establishes a missed 15-second drain deadline, without distinguishing delayed delivery, a stall, accounting behavior, or missing/duplicate records. Its cause remains unknown.

Follow-up runs pass exact global and per-connection count/byte assertions: repeated boundaries and reconnects, paused readers with backlogs exceeding 200,000 records, and synchronous sources. A replay compiled from the original archived runner, source, reader, and servers passes all 24 MVC/WebFlux measurement cases, with only failure-reporting instrumentation added. No WebFlux production fix is claimed, and a passing replay does not prove the timeout cannot recur. The original failed attempt and all diagnostics remain archived.

The local Phase 7 criteria are satisfied by the current passing test, publication, native, and measurement evidence. No required case, exact-count assertion, deadline, or retention threshold was removed or relaxed. The historical timeout is retained as an unexplained observation rather than a claimed fixed defect or confirmed data-loss finding. This assessment completes local implementation verification; it does not certify every deployment or authorize public publication.

Micronaut's direct-memory failure has a repeatable source/cleanup matrix and a production mitigation verified on all six Catnap stream modes. The [updated performance run](benchmarks/2026-11-16/http/attempt-4-micronaut/summary.json) passes all 12 cases and accompanies the full-build and native-image reruns; the throughput cost is explicitly recorded.

The subsequent [hosted snapshot verification](PUBLICATION.md#hosted-snapshot-verification) records GitHub Packages upload and fresh remote consumption of `3.0.0-SNAPSHOT` on Ubuntu 24.04. Release signing with real credentials, additional framework versions, and additional native-image operating systems remain outside the recorded evidence. The dated local records above preserve their original verification scope.

Legacy value predicates/JSONP, an SSE replay store, and incremental projection of one unbounded JSON document are explicitly outside this release's accepted scope. No hard real-time guarantee is claimed.
