# Java 17 launcher verification

A normal shell selected Java 17, so Gradle failed while loading Micronaut's Java 25 build plugin. The previous local verification explicitly supplied Java 25 through `JAVA_HOME`; compilation toolchains did not select the JVM loading the plugins.

The project now supplies `gradle/gradle-daemon-jvm.properties`, generated by `updateDaemonJvm --jvm-version=25`. Gradle selects or provisions a Java 25 daemon even when the wrapper starts on Java 17. The pinned Foojay settings plugin resolves missing compilation/test toolchains. Independent publication consumers receive the same daemon criteria, and CI's verification step deliberately starts the wrapper on Java 17. Library production sources and their bytecode targets are unchanged.

The [bootstrap log](bootstrap.log) records a Java 17 launch with custom JDK paths cleared and downloads enabled. Gradle downloaded Eclipse Temurin 25.0.5+8 and launched a single-use Java 25 daemon; `help` successfully configured the full build in 19 seconds.

The [full verification log](gradle.log) records `spotlessApply build compatibilityTest publicationSmokeTest` with the same Java 17 launcher. It passed in 2 minutes 24 seconds: 589 tasks, 352 executed, 13 restored from cache, and 224 up-to-date. Current reports contain 188 passing core tests on each of Java 17/21/25 and 275 passing consumer tests in each metadata mode, without failures, errors, or skips. The [summary](summary.json) records commands, counts, and changed build-input hashes. Unchanged test tasks may reuse previous outputs. CI YAML was validated locally; a hosted run was not performed.
